# 动态选币（每小时成交量突变轮换）

> 写于 **2026-10-09**。阈值都在真实市场上跑过校准；文中标注了哪些是实测数据。

## 1. 为什么要有它

固定盯一批品种有两个问题：形态越来越像（相关性高，机会重复），以及**漏掉突然启动的
品种**。这个模块每小时扫一遍全市场，挑出"昨天前天都是平常量、今天突然爆量"的品种，
换进监控列表。

代码：`pa_agent/orchestrator/screener.py`（纯逻辑 + 数据源适配，币安/OKX 通用）。
命令行自测（只读公开行情，不下单）：

```sh
uv run python -m pa_agent.orchestrator.screener --venue binance --count 2
```

## 2. 算法

对每个候选品种拉 300 根 1h K 线（≈12.5 天，**只用已收盘的**），用 USDT 成交额算：

| 量 | 含义 |
|---|---|
| `R6` | 最近 6 根成交额之和（"现在有多热"） |
| `med` / `sigma` | 过去 7 天所有 6 小时滚动窗口的**中位数** / `1.4826×MAD` |
| `burst` | `(R6 − med) / sigma` —— 突变强度 |
| `ratio` | `R6 / med` —— 放大几倍 |
| `D0 / D1 / D2` | 最近 / 前一个 / 再前一个 24 小时成交额 |
| `persist` | 最近 6 根里超过基线 p90 的根数 |

**为什么用中位数 + MAD 而不是均值 + 标准差**：我们要找的信号本身就是"方差特别大"，
用均值/标准差的话，**信号会把自己算进基准里**——越剧烈的行情反而越不显著。

硬门槛（全部满足才入选）：

| 门槛 | 默认 | 对应你要的 |
|---|---|---|
| `D0` 在成交量区间内 | **800 万** ~ 4 亿 USDT | "本身交易量又挺多的"；上限顺便把大币整体排除 |
| `burst ≥` | 6.0 | "突然放量" |
| `ratio ≥` | 3.0 | "方差特别大" |
| ~~`D0 ≥ 2.5 × max(D1, D2)`~~ | —— | **2026-10-10 降级为加分项**（见下） |
| `max(D1,D2) ≤ 2.0 × 日线中位数` | 2.0 | "昨天、前天都没什么交易量" |
| `R6 ≥` | **100 万** USDT | 绝对量兜底，防噪声币 |
| `persist ≥` | **2 根** | 一根尖峰＝刷量/插针，不算 |
| **快速通道** | 最近 2 根都 ≥3×p90 | **2026-10-10 新增**：约 1~2 小时就能触发 |
| 点差 ≤ | **15 bp** | 小币真正的杀手是点差 |
| 盘口深度 ≥ | **2 万** USDT | 见下面「流动性三道闸门」 |
| 零成交 K 线占比 ≤ | 10% | 自动识别股票类合约（每天有整点不成交） |

### 流动性三道闸门（2026-10-09 上调）

成交量是有量的**历史**证明，不等于**现在**接得住你的单子。所以有三道：

1. **24h 成交额 ≥ 2000 万 USDT**（原 200 万）——把薄币整体排除；
2. **最近 6 小时 ≥ 100 万 USDT**——防止"昨天很热、现在凉了";
3. **盘口深度 ≥ 2 万 USDT**：取**中位价 ±0.5% 内、买卖两侧里较小的一侧**的累计名义额。
   这一项只对排在最前面的少数候选验（一次请求一个品种），不扫全市场。

> 为什么不用"前 5 档"？因为它受最小变动价位影响极大。实测：**JCT 有 7850 万日成交额，
> 前 5 档却只有 2097 USDT**；换成本口径是 8596 USDT，才和别的币可比。
> 参考量级（2026-10-09 实测）：BTC 1859 万 / SOL 1483 万 / STRK 10.8 万 / MERL 1.6 万 /
> JCT 0.86 万 / Q 0.92 万。
> 按你的实际下单量（2 USDT 风险 ÷ 1.5% 止损 ≈ 130 USDT）算，2 万的门槛意味着
> 你的单子最多吃到可见深度的 0.7%。

排序分 = `burst + 3·log10(ratio) + 2·log10(D0/百万)`，取前 N（默认 2）。
两个入选标的还要做**相关性去重**：历史 1h 收益相关系数 ≥ 0.6 就跳过、顺延下一个，
避免同时押注同一个题材。

## 3. 实测（2026-10-09，币安）

全市场 497 个候选 → 粗筛后评估 98 个 → 成交额/突变达标 3 个 → **盘口深度再挡掉 2 个**，
最终只留 1 个（宁可少，不碰薄币）：

| 品种 | burst | 放大 | 今天/昨天 | 6h 成交额 | 24h 成交额 | 点差 | ±0.5% 深度 | 结果 |
|---|---|---|---|---|---|---|---|---|
| STRK-USDT-SWAP | 35.9 | 22.5× | 10.4× | 1.35 亿 | 3.27 亿 | 1.5 bp | 12.2 万 | ✅ 选中 |
| JCT-USDT-SWAP | 474.5 | 198× | 79.8× | 4159 万 | 7850 万 | 4.2 bp | 0.86 万 | ❌ 盘口太薄 |
| Q-USDT-SWAP | 10.2 | 11.1× | 6.9× | 3076 万 | 5490 万 | 9.0 bp | 0.92 万 | ❌ 盘口太薄 |

被门槛挡掉的典型（说明门槛在干活）：**AEVO**（burst 16.9 但 6h 只有 60 万 USDT）、
**MET / STRK 之外的旧热点**（"之前就已在放量"）、**MINA**（今天/昨天只有 0.7×）。

一次全量扫描约 1~2 分钟（粗筛后约 100 次 K 线请求），只在换榜时跑，不阻塞界面。

## 3.1 换榜周期：交易分析 30m、选币 1h（2026-10-09 定）

`watch_dynamic_refresh_min = 30`（分析周期 `watch_timeframe = 30m`）。理由：

- 信号的窗口是 **6 小时**，突变强度在几小时内衰变得很慢——2 小时后再选，通常还是同一批；
- API 请求和模型调用都减半：2 个品种 × 12 轮/天 = 24 次分析（1 小时选一次是 48 次）；
- 换榜只是换"看谁"，不增加分析次数（分析次数 = 品种数 × 收盘次数）；
- 交易分析用 **30m** K 线、选币用 **1h** 量能：换榜和 K 线收盘互相独立。
- 30m 下每次分析的 token 量与 1h 相同（都是 100 根 K 线），但次数翻倍：
  2 个品种 × 48 次/天 ≈ 860 万 tokens/天（1h 时约 430 万）。

## 4. 怎么开

`config/settings.json`：

```json
"general": {
  "last_data_source": "binance",
  "watch_timeframe": "30m",
  "watch_dynamic_enabled": true,
  "watch_dynamic_count": 2,
  "watch_dynamic_refresh_min": 30,
  "watch_dynamic_keep_static": false,
  "watch_dynamic_min_volume_usd": 8000000,
  "watch_dynamic_max_volume_usd": 400000000,
  "watch_dynamic_min_burst": 6.0,
  "watch_dynamic_min_window_usd": 1000000,
  "watch_dynamic_max_spread_bp": 15.0,
  "watch_dynamic_min_depth_usd": 20000,
  "watch_dynamic_exclude": []
}
```

- `watch_dynamic_keep_static=false`（默认）= **整个替换**监控列表；
  设 `true` 则保留 `watch_symbols` 里的底仓，把选出来的追加在后面。
- 已持仓 / 已挂单的品种不会入选（跳过也没意义，还会白花 token）。
- **没有挑到标的时沿用上一轮**，不会把监控列表清空；选币失败同理。
- 每轮换榜都会在日志里留一行 `动态选币换榜：[...]`，并带上突变强度与放大倍数。

## 5. 注意

- 这些是**小币**：点差比 BTC 大一到两个数量级，放量时往往已经涨了一截（追高风险）。
  程序只保证"每笔止损亏损不超过设定值"，不保证形态好。
- 数据源必须是 **7×24 的永续**（币安/OKX 都行）；股票类合约会被"零成交 K 线"门槛
  自动挡掉。
- 选币只看**成交量**，不看价格形态——形态判断仍然交给原有的两阶段分析。


## 6. 为什么改（2026-10-10 实测复盘：ZK 晚了 24 小时）

ZK-USDT-SWAP 的量能在 **10-08 23:00** 就启动（价 0.0111），但程序 **10-10 01:40**
才筛出来。拆开看延迟来源：

| 时间 | 滚动 24h 成交额 | 24h≥2000万（旧门槛） | 今天≥2.5×昨天 |
|---|---|---|---|
| 10-08 23:00（量能启动） | 10.0M | ✗ | ✗ |
| 10-09 23:00 | 21.7M | 首次"过" | ✗ |
| 10-10 02:00 | 40.7M | 过 | 首次"过" |

**≈24 小时卡在 24h 成交额 2000 万**（基线只有 700~1400 万，要放量满一天才能把滚动 24h
推过门槛），**≈3 小时卡在"今天≥2.5×昨天"**（天生要求放量满一天），剩下 1-2 小时是换榜
+收盘节奏。而量能规则本身当场就能达标。

改法：**流动性把关交给盘口深度**（当根就能验），成交额门槛降到 800 万；"今天/昨天"
降级为加分项；新增"连续两根爆量"快速通道；换榜 30 分钟。按 ZK 数据，改完会在
**10-08 23:00~10-09 01:00** 入选，提前约 24 小时。

## 7. 波动闸门：1h ATR%（2026-10-12 加，当前=只记录）

**起因**：10-12 实盘两笔止损（IO −2.07、RSR −2.13）都发生在"刚爆量大涨过"的小币上。
以 RSR 为例（2026-10-12 15:30 那笔）：

- K6（12:30 那根 30 分钟）开 0.001662 → 收 0.002356，低点 0.001659，成交额 61.9 亿
  ≈ 前一根的 **235 倍**；之后在 0.002266~0.002589 区间整理。
- 计划：回撤到 0.00233 做多，AI 的结构止损是 0.002265（2.79%），随后被程序的
  "RR ≤ 1.0 自动向外扩 stop"规则改成 0.002164（7.12%）。
- 15:55 成交，**18:00 那根 15 分钟 K 线从 0.002301 直砸到 0.002043（−11%）**，
  两个止损位一起被扫掉；两小时后价格又涨回 0.00248（高于入场价）。
- 该币 **30m ATR14 = 0.000131 = 5.5%**：AI 的结构止损只有 **0.50×ATR**、实盘用的
  也只有 **1.27×ATR** —— 对一根 ATR 5.5% 的币，这种距离属于噪音止损。

**结论**：问题不在"止损放在哪个结构位"，而在这类币**根本不适合**精确止损的入场。

**做法**（`orchestrator/screener.py`）：

- `atr_pct_of()`：用选币自己的 1h K 线算 `ATR14 ÷ 最新收盘 × 100`，挂到
  `Candidate.atr_pct`（算不出来时 = 0.0，表示"未知"，**不当成低波动**）。
- 两个新配置（`settings.general`）：`watch_dynamic_max_atr_pct`（0 = 不开闸门）、
  `watch_dynamic_atr_gate_mode`：
  - **`record`**：照常分析、照常下单，只在入选时记一条日志，并在换榜日志里带上
    `波动x%`，攒样本用。
  - `skip`：ATR% 超门槛的候选直接进 `reasons` 被排除，不会进监控列表。
- **2026-10-12 晚修正：当前机器把 `max_atr_pct` 设回 `0`（= 关掉这条固定比例闸门）。**
  用户指出：拿**固定百分比**（4%）当门槛不对——每个币的正常波动比例本来就不一样，
  BTC 的 2% 和 RSR 的 2% 不是一回事。所以换成用"**止损距离 = N×该币自己的 ATR**"
  来衡量（见第 8 节）。原始 ATR% 仍然**只作为信息**印在换榜日志里，不再做判定。

**回归测试**：`tests/unit/test_screener.py` 相关 7 条（ATR 计算、record 不拦、
skip 拦、门槛 0 = 关闭、缺 high/low 时返回 0、配置读取大小写不敏感、record 日志）。

## 8. 止损宽度的正确单位：N×ATR（2026-10-12 加，只记录不拦单）

用户的问题：「你怎么能用固定的 4% 这个比例呢？不同的币波动的比例是不一样的，
你应该拿它的 ATR 倍数来做比较吧？」——**对**。

按 1h/30m K 线算 `止损距离 = |入场 − 止损| ÷ ATR14`，它是**无量纲**的：
1.5×ATR 对 BTC 和对 RSR 是同一件事（都表示"离这个币的正常噪音 1.5 倍远"）。

**当天 32 条计划的实测对比**（`|入场−止损|` 按百分比 vs 按 ATR 倍数）：

| 计划 | 止损% | 止损 ×ATR |
|---|---|---|
| CHIP 01:00 | 1.10% | **0.34×** |
| GRASS 16:00 | 1.46% | **0.37×** |
| RSR 15:30（实盘成交） | 7.12% | **1.27×** |
| IO 13:41（实盘成交） | 4.49% | **1.49×** |
| RSR 19:02 | **14.86%** | 1.67× |

看最后两行：百分比差了 3 倍多，ATR 倍数只差 10%。**百分比这个单位在跨品种时
没有可比性**，这正是要换单位的理由。

**实现**（`util/trade_metrics.py` + `ai/stage2_normalizer.py`）：

- 纯函数 `stop_atr_multiple(entry, stop_loss, atr)`、`atr_from_frame(frame)`、
  `decision_stop_atr_multiple(decision, frame)`；
- 规范化阶段（和 "RR ≤ 1.0 扩 stop" 同一处，那里正好有 K 线帧）对每个可执行计划
  记一条 WARNING：
  `计划止损宽度：RSR-USDT-SWAP 30m 入场 0.00233 / 止损 0.002164 → 1.27×ATR（偏窄：不到 1.5×ATR，容易被噪音扫掉）`
- 参考线 `NARROW_STOP_ATR_MULTIPLE = 1.5` **只用于提示**，不拦单。

**为什么不现在就拦**：把当天 9 笔成交/回放成交的计划按倍数排一下——
**赢的两笔是 0.37× 和 0.94×，输的六笔是 0.34×、0.70×、0.71×、1.01×、1.27×、1.49×**
——完全没有分离度。也就是说"止损太窄就会被扫"这个机制本身成立（RSR 那根 15m 走了
止损距离的 3 倍），但**今天的数据不足以证明某个倍数门槛能提高胜率**。先当尺子用，
攒几天样本再决定要不要设下限。

**2026-10-12 20:2x 实测的 1h ATR%（币安，只读）**，用于标定阈值：
RSR 7.54%、MUBARAK 5.46%、METIS 4.82%、PLUME 4.53%、GRASS 4.39%、IO 4.21%、
DATAIP 3.32%、DYM 3.24%、RED 3.23%、RVN 3.21%。按 4.0% 门槛，当日会命中前 6 个
（含实盘亏钱的两笔 IO/RSR），也包含那笔被门槛拒掉、事后回放会赢的 GRASS —— 说明
这条闸门**不是稳赚的改进，是"少做几笔换少被噪音扫"**，所以先只记录。

回归测试：`tests/unit/test_screener.py` 第 7 节相关 6 条（ATR 计算、record 不拦、
skip 拦、门槛 0 = 关闭、缺 high/low 时返回 0、配置读取大小写不敏感）。
